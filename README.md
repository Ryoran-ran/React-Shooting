# BLUE CURRENT

イルカと、青の向こうへ。画面干渉型シューティングゲームの **Phase 2：戦闘プロトタイプ** です。既存の画面サイズと、背中を上から見たイルカのデザインを維持しています。

## 起動

Node.js 22.12 以上（22 系）または 24 以上と npm を使用します。

```powershell
npm install
npm run dev
```

ブラウザで <http://127.0.0.1:5173/> を開いてください。PC とキーボード向けです。別アプリやタブに移動すると自動でポーズします。戻ったら Esc または「泳ぎを再開」で再開できます。

| キー | 操作 |
| --- | --- |
| 矢印 / WASD | 移動（斜め移動も同じ速さ） |
| Z / Space 長押し | 連射 |
| Shift 長押し | 低速移動 + 追尾ショットに切替 |
| Esc | ポーズ / 再開 |

起動すると戦闘練習が始まります。右パネルの「敵との戦闘」を OFF にすると、従来の操作練習へ切り替わります。モード切替時は HP・時間・弾・敵・練習設定を初期化します。ロックオンマーカーは表示しません。

戦闘中の「敵の攻撃」を OFF にすると敵弾とレーザーの予兆・発射を解除し、射撃なしで敵を撃つ練習ができます。**敵本体への接触判定は残ります。** 操作練習モードのクラゲには撃破・衝突判定がありません。

## 実装範囲

- React・TypeScript・Vite・PixiJS による 1280×720 の画面。左右 280×720、中央 720×720。全体を等比率でリサイズ。
- 背中を上から見た水色の仮イルカ。左右の胸びれ・背びれ・尾びれを描画。尾びれの泳ぎ、移動時の傾き、低速時の穏やかな動き、発射エフェクト。
- 通常 300px/s、低速 120px/s。境界内への制限、生存中は半径 4px の判定点を常時表示。
- 直進ショット：間隔 0.12 秒、速度 600px/s、威力 2。
- 追尾ショット：間隔 0.20 秒、速度 450px/s、威力 1、旋回上限 180°/秒。正面との角度が小さい対象を優先し、同角度では近い対象を優先。
- 発射時の対象を追尾。対象消失後は最後の方向へ直進し、別対象を取り直しません。対象不在時は正面へ発射。
- 60Hz の固定タイムステップと描画補間。連射間隔はゲーム時間から計算。
- ポーズ、入力の解除、非アクティブ時の自動停止、リセット、初期化失敗時の案内。
- HUD は 10Hz で更新し、毎フレームの React 再描画を回避。
- 小型（クラゲ）・中型（ハリセンボン）・固定砲台（イソギンチャク）・突進型（イカ）・大型（マンタ）の5種。見た目・性能は敵データとして分離。
- イカは自機に接触すると爆発して消滅。接触ダメージは通常どおり1で、無敵中は無傷でもイカは爆発する。接触による自爆では撃破数・ドロップを発生させず、ショットで倒した場合は通常の撃破として扱う。
- 42秒の固定パターンを繰り返す戦闘練習。出現時間・位置・種類・移動・退場時間を外部データで定義。
- 直線・波状・ジグザグ・追尾・定位置への移動と停止・指定経路の6種類の移動。
- 直進弾・発射時の自機狙い弾・予兆付きレーザー。攻撃間隔と大型敵の残HPによる追加攻撃を設定可能。
- レーザーは予兆開始時に射線を確定。予兆1.2秒中は無害で、その後0.65秒だけ接触判定が発生。
- 追尾ショットは出現済みで生存中の敵を対象にする。撃破・退場した対象は追い直さず、最後の方向へ進む。
- World座標で円形判定。前フレームからの相対移動も判定し、高速弾のすり抜けを防止。自機弾は手前の敵1体に命中して消える。
- 自機の判定半径4pxと見た目を分離。敵本体・敵弾・発射中のレーザーでHPが1減少。被弾後1.5秒は無敵になり、点滅・波紋で表示。
- 敵の撃破・被弾・回復のエフェクト、敵の残HP、自機HP・回復ゲージ・撃破数・敵弾数を表示。
- 撃破した通常敵の弾は残存。退場は撃破に数えず、アイテムも落とさない。
- 滞在時間切れ・経路終了時は攻撃を止め、近い上端・左右端へ加速して退場。姿が完全に画面外へ出てから削除。退場中も撃破は可能。
- 回復アイテムは緑の「＋」。接触取得でゲージ+20、100でHP+1、余剰は繰越。HP最大時は蓄積せず、HP0からは回復しない。
- ドロップ率は小型15%、中型40%、固定砲台50%、突進型15%、大型100%（2個）。乱数はリトライで同じシードに戻す。
- HP0で全弾・レーザーを解除して戦闘を停止。イルカが1.2秒かけて下へ落ち、消えてからリトライ画面を表示。「リトライ」でHP10、回復ゲージ0、敵の出現順も最初から再開。落下は表示だけの演出で、内部の自機座標と経過時間は変えない。

## 動作確認

```powershell
npm test          # 純粋なゲームロジックと入力ライフサイクル
npm run build    # TypeScript 型チェック + 本番ビルド
npm run preview  # 本番ビルドをローカルで確認
npm run test:e2e # インストール済み Google Chrome でブラウザテスト
```

E2E は開発サーバーを自動起動します。Chrome がない環境ではインストール後に実行してください。スクリーンショットは `artifacts/` に保存します。

手動確認のポイント：

1. 矢印 / WASD で泳ぎ、画面端でもイルカがはみ出さないことを確認。
2. Z を押したまま Shift を押す・離す。弾の色、移動速度、ショットの直進 / 追尾が変わることを確認。
3. 開始約1.2秒後からクラゲが出現すること、ショットで敵が消え、撃破数が増えることを確認。
4. 赤い敵弾・敵本体に触れ、HPが1減ってしばらく点滅することを確認。無敵中にHPが連続して減らないことを確認。
5. 開始約13秒以降のイソギンチャクの予兆線を確認。細い予兆線は無害で、太く光ってから危険になることを確認。
6. 緑の「＋」アイテムを取得。HPが減った状態で5個集めると1回復し、最大HPではゲージが増えないことを確認。
7. HP0で戦闘が止まり、イルカが落下してからリトライ画面が出ることを確認。「リトライ」でHP10・ゲージ0・撃破数0・最初の敵配置に戻ることを確認。
8. Esc で敵・弾・レーザー・回復アイテム・無敵時間も止まることを確認。別ウィンドウへ移動後に入力が残らないことを確認。
9. 「敵の攻撃」を OFF にして敵弾・レーザーが消えることを確認。「敵との戦闘」を OFF にして、従来のクラゲの表示・移動を確認。
10. 操作練習で追尾弾が飛んでいる間にターゲットを消し、直進を続けることを確認。
11. リセットとブラウザのリサイズを確認。16:9と中央の正方形、既存の画面サイズを維持。
12. Shiftを離しても判定点が見えることを確認。倒さずに残した砲台・大型敵が、時間切れで画面端へ移動して退場することを確認。

## コード構成

```text
src/
  app/                 React の画面・HUD・リサイズ・ゲームの接続
  game/
    config.ts          調整用の仮数値（秒、ワールド座標 px）
    core/              ゲーム状態、固定更新ループ、座標変換
    entities/          自機・自機弾・敵・敵弾・レーザー・アイテムのデータ
    systems/           入力、移動、出現、攻撃、衝突、被弾、回復、撃破・ドロップ
    stages/            エリア・固定出現パターンの定義
    rendering/         PixiJS による描画のみ
  data/enemies.ts      敵のHP・見た目・当たり判定・射撃・ドロップ設定
  tests/               Vitest の単体テスト
e2e/                   Chromium での操作・リサイズ確認
```

`Game` は DOM・React・PixiJS を参照しません。移動・追尾は World 座標で処理します。`state.field` が移動範囲、`state.view` が表示の拡大・回転・移動を担い、独立しています。`coordinates.ts` に相互変換関数があり、描画側が View を適用します。React の左右パネルは Pixi のシーンから分離しています。

`game/config.ts` で速度・発射間隔・旋回速度・被弾・回復等、`data/enemies.ts` で敵の性能、`game/stages/trainingGround.ts` で出現パターンと簡易ターゲットを調整できます。将来のギミックを入れる余地を残し、高度なギミックエンジンや登録機構は実装していません。

移動・攻撃・当たり判定・ドロップは描画から独立しています。通常敵の弾とレーザーは発射元への参照を保持しないため、発射元を撃破・退場させてもそのまま残ります。敵の退場と撃破は別経路で処理します。

## 未実装（次フェーズ以降）

タイトル・ステージ選択、ボスとフェーズ切替、ステージクリア・結果画面、スコア計算・評価・localStorage、BGM・効果音、画面干渉ギミック。

HP・回復ゲージ・撃破数は実データです。SCOREは未集計の000000、BEST SCOREは未記録の「—」です。ステージ進行・クリア判定はなく、敵のパターンを繰り返す練習エリアです。HP0の停止とリトライはPhase 2の動作確認用の最小限の画面です。

敵や弾の性能・配置・ドロップ率は仮調整です。好みの難易度に合わせた本調整と、一定数ドロップしなかった場合の保証処理は今後の課題です。

依存バージョンは `package-lock.json` で固定しています。[Vite の導入要件](https://vite.dev/guide/) と [PixiJS の Application](https://pixijs.com/8.x/guides/components/application) に従った構成です。
